# 军械库光照材质经验

更新时间：2026-08-16

适用项目：网易 ModSDK / Minecraft 中国版军械库资源包与行为包  
重点范围：手电后处理、深度遮挡、表面受光、PBR 材质接入决策

## 结论先读

最适合沉淀这类经验的格式是 Markdown。原因是 GitHub 可直接预览，能放代码片段、参数表、测试清单和踩坑记录，也方便后续 AI 读取。

本轮最有效的手电方案不是完全替换成参考包的重型体积光，而是在老版稳定光圈基础上叠加三个低风险模块：

1. `depth_anchor` 后处理 pass，确保深度链路稳定。
2. Python 端方块射线遮挡距离，给 shader 一个第一个实体方块的最大照明距离。
3. shader 内低步数屏幕空间接触阴影 + 软表面受光门控。

当前稳定方向：保留老版手电光圈和亮度手感，只把“遮挡关系”和“只有能照到的面更亮”补上。

## 不要再从零开始的关键经验

### 1. PBR 环境图本轮不应继续

尝试过把 PBR 环境 atlas 接入默认/流畅 PBR shader，但实测效果不如原版，已经撤回。后续 AI 不要误以为这是待完成项。

保留原则：

- 不改 `eplusPBRBalance.h`。
- 不重新接入 `ep_env_irradiance`、`EPLUS_USE_ENV_ATLAS`、`eplus_env_irradiance`。
- cubemap/HDR 可以作为离线制作参考，但当前游戏运行时不要重新引入 PBR atlas。

### 2. 手电中心硬线的高风险来源

之前最严重的问题是在平地约 4 格距离出现明显横向/分割线。这个问题不是单纯颜色或亮度问题，而是算法本身在深度图上产生了硬分界。

高风险做法：

- 用全屏左右/上下深度对称采样重建法线，然后让主光强依赖这个法线。
- 在深度不可信时回退成硬阈值，而不是软衰减。
- 让空气光束或白雾承担表面增亮职责，会导致“照到哪里都平”。
- 沿屏幕 UV 从灯点到像素做直线遮挡采样，这不是实际光路，阴影关系很弱。

结论：任何会让主照明直接受全屏深度断层、对称采样、硬阈值控制的方案，都可能再次出现分割线。

## 稳定有效的做法

### 1. 先恢复老版光效作为基线

老版 `lamp.glsl` / `lamp_fast.glsl` 的光圈、亮度和手感比较稳定。不要直接用参考包完整 shader 覆盖它。

正确路线：

- 老版负责光圈、中心热斑、边缘柔光、眩光基础。
- 新算法只负责深度遮挡、接触阴影、表面受光关系。
- 这样每次出问题可以判断是“光型问题”还是“遮挡问题”。

### 2. 深度锚点 pass 很有价值

增加 1x1 的 `eplus_depth_anchor` 后处理 pass，开启 `depth_enable: true`，shader 内采样 `TEXTURE_2`。它的作用不是产生视觉效果，而是帮助后处理链路稳定持有深度图。

经验：

- anchor pass 常开。
- 输出只轻微依赖深度和 `EXTRA_VECTOR1.x`，默认值为 0。
- 不新增贴图，不新增复杂配置。

### 3. Python 端方块遮挡距离适合做第一层防穿墙

在 `lamp.py` 中从手电发射点沿方向步进，使用 `GetBlock()` 和 `GetBlockCollision()` 找第一个有碰撞盒的非透明方块，写入 `EXTRA_VECTOR4.x`。

建议参数：

```text
最大距离：32.0
步长：0.5
未命中：10000.0
默认模式刷新：每 2 次 update
流畅模式刷新：每 5 次 update
```

注意：

- Python 必须兼容 2.7。
- `GetEngineCompFactory()` 缓存在文件顶部。
- 跳过空气和名称含 `glass` 的方块。
- 不要在 `setFastMode()` 里复用 `EXTRA_VECTOR4` 表示快慢模式，快慢模式只由 pass 启用决定。

### 4. 参考包真正有阴影关系的核心是“世界光路线段投影”

参考包的强点不是颜色，而是从当前表面点到手电发射点之间沿光路线段采样，再投影回屏幕读取深度。如果途中有更近的可见几何体，说明光被遮挡。

当前项目里的稳定低成本版本：

```text
默认模式：5 步接触阴影
流畅模式：2 步接触阴影
遮挡结果：软降低亮度，不直接打到全黑
```

关键思路：

- 保持 `fromPos` 和 `toPos` 在同一坐标系。当前工程中使用相机相对位置更安全。
- 用 `worldToClip = WORLDVIEWPROJ * inverse(WORLD)` 投影采样点。
- 用 `inverse(WORLDVIEWPROJ)` 从深度图重建采样点位置。
- 跳过离相机太近的一人称枪身/手部模型，避免手电给自己投假阴影。
- 只在 `earlyLight` 通过后再计算遮挡，控制性能。

### 5. “只有照到的面更亮”应使用软表面门控

用户明确要求：任何改变方块/生物/枪身表面亮度的层，都要遵守只照能照到的面的规则。

当前稳定做法是 `surfaceLightGate`：

- 用中心深度 + 右侧一点 + 下方一点重建一个轻量伪法线。
- 用软 Lambert 判断表面是否朝向手电。
- 加入 `confidence`，深度不可信时不硬切，只回退到保守亮度。
- 默认模式效果更明显，流畅模式更保守。

这比之前全屏强法线方案稳定，因为它不会把低可信区域变成硬分界。

建议规则：

```text
主表面增亮：乘 surfaceGate
中心热斑：乘 surfaceGate
边缘光：乘 surfaceGate
空气/柔光：只乘较弱 beamGate，避免完全消失
眩光：主要受遮挡控制，不要强行法线化
```

### 6. 深度和矩阵计算必须高精度

后处理里涉及深度重建、矩阵逆、世界/相机空间距离比较时，尽量使用 `highp`。

尤其要保持：

- 深度采样变量用 `highp float`。
- 重建位置用 `highp vec3`。
- `invWVP`、`worldToClip` 用 `highp mat4`。

这不能保证完全消灭所有平台差异，但能明显降低深度量化和远距离抖动。

## 参数经验

### 当前较稳参数

默认模式：

```text
CONTACT_SHADOW_STEPS = 5
CONTACT_SHADOW_BIAS = 0.18
CONTACT_SHADOW_THICKNESS = 3.0
CONTACT_NEAR_MODEL_DIST = 1.5
CONTACT_LIGHT_CLEAR_DIST = 1.0
SURFACE_TEXEL_X = 0.00135
SURFACE_TEXEL_Y = 0.00185
```

流畅模式：

```text
CONTACT_SHADOW_STEPS = 2
CONTACT_SHADOW_BIAS = 0.22
CONTACT_SHADOW_THICKNESS = 3.2
CONTACT_NEAR_MODEL_DIST = 1.5
CONTACT_LIGHT_CLEAR_DIST = 1.0
SURFACE_TEXEL_X = 0.00155
SURFACE_TEXEL_Y = 0.00205
```

### 调参原则

- 如果阴影太弱，先小幅提高 `blocked` 权重，不要增加大量采样步数。
- 如果出现线，优先降低 `surfaceGate` 的影响或放宽 `confidence`，不要直接删遮挡。
- 如果平地再次出现硬切，重点检查法线门控是否变成硬阈值。
- 如果移动端卡顿，先降低默认模式接触阴影步数到 4，流畅模式保持 2。

## 测试清单

每次改手电算法都要至少测这些场景：

1. 夜晚平地照射 4-8 格，准星缓慢上下左右移动，看是否出现固定分割线。
2. 平墙近距离和中距离照射，看中心光斑是否连续。
3. 墙角、台阶、方块边缘，看朝光面是否更亮，背光面是否被压住。
4. 生物正面、侧面、背面照射，看是否有方向感但不硬断层。
5. 第一人称枪身和手电近距离照射，看是否出现假阴影、过曝或变黑。
6. 默认/流畅模式分别测试，流畅模式允许立体感弱一些，但不能明显掉帧。
7. 回归检查 PBR atlas 关键词无命中。

## 后续可继续优化的方向

### 1. 低步数体积光

参考包有 24 步体积光和 12 步阴影，效果强但移动端风险高。后续可尝试：

```text
默认模式：6-8 步体积光
流畅模式：0-4 步体积光
```

体积光只负责空气光束，不负责表面增亮。

### 2. 一人称发射点偏移

参考包在一人称中把灯点从相机中心偏到手的位置，这会让光源更像从手电发出，而不是从准星或眼睛发出。

可以考虑在 Python 端根据相机 forward 计算 right/up 偏移：

```text
右偏：约 0.35
下偏：约 0.28
前偏：约 0.25
```

这可能改善真实感，但会改变当前枪械手感，需要单独测试。

### 3. 冷白色和轻微曝光

用户偏好白到微蓝的冷光，中心允许轻微曝光。可以在当前 `lampColor` / `hotColor` 基础上小幅调冷。

注意不要直接把白色盖上去，否则又会变成白雾和平面感。更适合用类似线性减淡/曝光曲线，但要限制上限。

## 给后续 AI 的提醒

- 先读现有 shader，不要凭记忆重写。
- 查 ModSDK 文档后再动 API，事件和参数名不要猜。
- Python 保持 2.7 兼容。
- 不要把参考包资源直接复制进项目，只参考算法思路。
- 不要一次性引入完整体积光、屏幕阴影、PBR 和颜色重调。每次只改一个变量，进游戏观察。
- 用户对“平地 4 格硬线”非常敏感，任何算法只要可能产生硬阈值，都要优先软化。
- 当前成功经验是：老版光型 + 深度锚点 + 方块遮挡距离 + 低步数接触阴影 + 软表面门控。
